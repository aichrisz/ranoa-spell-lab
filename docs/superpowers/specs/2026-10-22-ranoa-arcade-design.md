## Core rules (exact acceptance contract)
- Logical world 900×560. Draw/scale with consistent coordinate mapping, no stretching or input drift at any responsive size/DPR.
- A run is exactly 60 active gameplay seconds. Ready/paused/hidden time does not consume the run. Finish at zero once and reject further casts; replay resets targets, mana, combo, stats, timers and transient effects.
- Mana max100, regeneration12 per active second, clamp to max. Costs: Water Bolt10, Aqua Burst28, Frost Ring22. Suggested cooldowns 0.15/0.65/1.2 seconds; disclose them in instructions if implemented.
- Water Bolt: precision single-target hit near the chosen point. Aqua Burst: radial damaging hit at aim point (radius100 world units), can destroy multiple targets. Frost Ring: radius140, slows targets within the ring to35% speed for4 active seconds, no direct damage. Separate effect lifetimes from browser animation.
- Each target destroyed earns100×multiplier. Consecutive damaging successful casts advance combo; one burst cast advances combo once even if it destroys multiple targets. Multiplier=1+floor(combo/5), capped5. Display and test the chosen pre/post-increment scoring order explicitly. A valid damaging miss resets combo. Frost hit counts as a hit for cast accuracy but does not artificially increase combo/score; frost miss resets combo. Insufficient mana, cooldown, invalid/NaN/out-of-world aim or casts while inactive are rejected without spending mana, changing accuracy or resetting combo.
- Accuracy = successful accepted casts / accepted casts; never >100%, zero casts displays0%. Best combo is maximum consecutive damaging hits, not final combo. Keep integer score.
- Start with at least3 visible targets; spawn progressively (initial interval around1sec), cap targets at12. Radius around30–44 world units; adequate hit tolerance on mobile. Targets drift/bounce within arena and expire after a bounded life; use shapes/labels beyond just color. Difficulty can increase modestly during the run without making targets impossible to hit.
- Engine must be DOM-free and accept injected random/seed and explicit dt. Reject or safely ignore invalid dt, ensure large steps do not overshoot finish or move while paused. Deterministic simulation tests independent of real time. Never use the render frame count as elapsed time.

## Input, usability and accessibility
- Pointer/touch aim and release casts. Prevent scrolling only during active gestures on the canvas, not across the whole page. Cancelled pointers/drag outside do not unexpectedly cast; don't let secondary/right clicks cast.
- HTML spell selectors with visible names, mana costs, pressed/selected state, >=44px targets; shortcuts1/2/3. Canvas focusable and described with readable keyboard instructions.
- Full keyboard path: arrows move reticle, Space casts when canvas focused; T cycles/aims to live targets (a legitimate assistance mechanic, not a hidden testing backdoor); Enter/Space native buttons start/replay/pause. Keyboard shortcuts must not steal typing or native button/checkbox activation. Escape/P pauses with a visible resume action.
- UI Start/Pause/Resume/Replay states are coherent and keyboard accessible; focus is moved intentionally on overlay transitions. Do not leave focused elements hidden or trap keyboard. A screen-reader status region announces important actions/results without updating the entire HUD60fps.
- Pause automatically on visibility hidden/window blur and require explicit resume, so no surprise casts or time loss after returning. Reset rAF clock on resume; no huge catch-up delta. One render loop only; it may stop while paused/hidden/results if no needed updates.
- Honor reduced motion and offer an effects toggle. Reduce decorative trails/shake/particles, but retain essential target movement and visible hit cues; never stop the actual game's targets just because reduced motion is enabled. Explain the difference in UI. No flashing/autoplay audio.
- Safe bounded localStorage personal-best schema under a project-specific key; unavailable/malformed/negative/non-finite storage does not break game or render HTML. Do not store PII. Use textContent, not unsafe HTML. No hidden test-mode query parameters in production.
- At widths320/390/768/1024/1440, no horizontal overflow, cropped controls or overlay text; Start and core controls usable in portrait. Pointer mapping remains correct after resizing/orientation changes and at DPR2. Respect deviceScaleRatio with a sensible cap.
- Correct landmarks/headings, contrast, visible focus, keyboard native buttons. Axe WCAG2A/AA/2.1AA + best-practice checks ready, running, paused and results. Canvas spatial gameplay cannot be certified fully accessible by axe alone; document limits honestly.

## Architecture and deliverables
Use dependency-free browser JS and Canvas2D; separate engine.js (pure gameplay), renderer.js (Canvas and bounded cosmetic particles), app.js (DOM/input/state/storage/loop), styles.css, index.html and original assets/sigil.svg. Prefer classic deferred scripts/IIFEs with a single namespaced API so the source and bundled HTML work via file:// without a server. Expose engine for Node unit tests using a harmless CommonJS export or equivalent, without a test-only mutable window game hook. Renderer must not own score/time logic.

Node built-ins for local loopback dev server, explicit public-file allowlist build and one-file offline export. No symlink/private-path exposure, cwd-relative destructive builds, eval, third-party runtime code or service installation. Exact dev-only pins @playwright/test1.64.1 and axe-core4.14.0 (npm install --ignore-scripts); formatter optional pinned one-off, not a runtime dependency. Existing Chromium /root/.hermes/tools/chromium-1208/chrome-linux/chrome with CHROMIUM_PATH override.

Required commands: npm run check; npm run test:unit (Node test runner); npm run test:e2e (Playwright); npm test (both); npm run build; npm run export; npm audit. Build static dist is tested separately if supported. Export artifacts/Ranoa-Spell-Lab.html embeds all app scripts/CSS/SVG and works offline. Source ZIP must exclude node_modules/.git/private data, and screenshots show actual ready and active gameplay at desktop/mobile. README documents mechanics, exact controls, architecture diagram, real test outcomes and limitations. docs/tdd-evidence.md contains actual observed red/green results, not invented claims.
